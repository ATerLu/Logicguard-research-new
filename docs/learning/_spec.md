# LogicGuard 项目完整框架学习手册规格

## 目标

帮助重新接手项目的读者从全局理解 LogicGuard 的研究问题、代码分层、攻击—检索—防御—回答—审计主链、比较实验治理和当前未完成事项。

## 默认读者

- 小白：能看懂 Python，但不熟悉 RAG / GraphRAG / 研究实验。
- 后端开发者：关注模块边界、数据契约、调用链和配置驱动运行。
- 研究者/老手：关注威胁模型、控制组、指标分母、oracle 边界和研究就绪度。

## 范围

覆盖当前 `uisee-dev` HEAD `1bad5928753a786261d98637094115334eba3fbf`：

1. `data → graph/naive_rag` 的透明原型；
2. `attack → defense → ms_graphrag → evaluation` 的实验主链；
3. `benchmark` 的协议、公平控制、成本治理和 dev60 冻结；
4. D5 现有 Stage43–45 与尚未实现的 D6 四组件设计；
5. WP1–WP5 当前状态与安全学习路径。

## 不做的事

- 不把历史阶段结果包装为正式论文结论。
- 不把 D6 描述为已经完成的生产防御。
- 不执行真实 provider、索引或付费实验。
- 不修改仓库源码、冻结资产或配置。

## 验收标准

- 至少 2 张 Mermaid 图：整体架构、端到端链路。
- 主体包含类比、逐步流程、源码定位、额外知识框和章末一句话总结。
- 至少 15 个源码定位链接，内容基于上述 commit。初稿使用本机绝对路径；Git 归档版改为固定 commit 的 GitHub `#L` 链接，图与配套文档使用仓库相对路径。
- 明确区分：早期透明原型、官方 GraphRAG 实验链、benchmark 治理层；D5 与 D6；方法与验证基础设施。
- 给出新人阅读顺序、离线测试命令和至少 3 个练习。

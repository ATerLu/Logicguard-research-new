# LogicGuard 研究进度独立评审意见

_第三方评审视角；2026-08-07；评审范围：截至 Stage47 的全部实验记录、代码与结果文档_

> 本评审刻意不参照 `docs/thesisPlan.md` 的既定路线，仅基于实验证据本身评估研究的科学有效性、问题与后续方向。

## 一、总体评价

**做得好的地方**（必须承认，这些是稀缺品质）：

- 评测纪律严格：攻击漏斗分母分离（attempted / generation_valid / evaluation_valid / prompt_exposed / targeted_success）、broad ASR 与 targeted ASR 分离、prompt 截断后预检、judge 按需调用、边界声明诚实（"这是 oracle 上界""这只是 post-retrieval 扰动"）。大多数已发表论文做不到这个水准。
- 归因驱动的迭代方式（Stage29–39）是规范的实验科学：每步先离线诊断瓶颈、做假设、修复、真实 LLM 复验，还排除了错误假设（prompt 调优无用、BM25 rerank 有害）。
- 自我攻防（Stage47）的诚实度罕见：主动证明自己防御有三个缺口，而不是藏起来。

**但作为学位论文/科研成果，目前的科学主张（scientific claim）还没有站住。** 下面按严重性排序讲问题。

## 二、核心问题

### 问题 1（致命）：整个防御建立在"可信干净候选池"这个未论证的假设上

这是房间里的大象。从 Stage23 到 Stage46，所有 recovery 的本质是：**存在一个 trusted clean reference pool，里面有污染文档的干净对应物**，防御就是从里面把干净版找回来。Stage28/43 去掉了 doc_id oracle，但"干净池存在且覆盖污染文档"这个假设从未被动摇过。

请问：**攻击者既然能污染知识库，为什么污染文档的干净副本会天然存在？** 如果攻击是注入一篇全新的文档（而不是改写旧文档），池子里根本没有对应物——Stage47 自然桥接攻击恰恰就是利用这一点打出 0.875 ASR 的。**也就是说：防御假设和最大攻击缺口是同一个东西。** 这不是巧合，这说明当前方法有效性的边界完全由这个假设划定。

可能救这个假设的说法是"部署方有版本快照/签发历史"（比如企业知识库有 git 式的历史版本）。可以，但必须：

1. 把它明确写进威胁模型，作为部署前提而非隐含假设；
2. **实验上构造"可信池 = 污染前的历史快照"的具体设定**，而不是一个抽象的 clean pool；
3. 测量池覆盖率 <100% 时防御如何退化（覆盖率扫描实验）。

现在这三件事一件都没做。评审第一个问题就会问这个。

### 问题 2（严重）：检测器是被 LogicPoison 的生成结构"喂"出来的

看 Stage43 数据：HotpotQA 替换了 **662/662** 个 source，MuSiQue 629/633。这说明当前"检测"实际上是"把几乎所有 source 都换成同名干净版"——不是选择性检测，是全量替换。项目自己的文档也承认了这一点（"尚未证明混合语料中的高选择性风险检测"），但应该说得更重：

风险检测的核心条件是"标题与 clean candidate 高度相似 + 实体漂移大"。这正好精确匹配 LogicPoison 攻击的生成方式（同标题、改写内容）。**防御规则是针对这一个攻击生成器的产物结构设计的，risk_recall 0.99 是这个匹配的必然结果，不是检测能力。** Stage47 低漂移攻击（改数值不改实体）立刻把检出率打成 0，已经证明了这一点。在混合语料（clean + 多个不同攻击族 + 大量无关文档）下的 precision/recall 完全未知。

### 问题 3（严重）：实验规模与统计有效性不足以支撑数字

- **每数据集 20 个 query**。final utility 0.95 就是 19/20——一个 query 的变化就是 5 个百分点。0.85 和 0.95 的差距是 2 个样本。这些数字没有置信区间、没有多种子、没有显著性检验，却用四位小数书写（`0.9500`），这本身就给人一种超出实际的精确感。
- **阈值在测试集上调的**。title_overlap=0.80、entity_drift=0.10、top-k=5 这些"冻结参数"，是在同一批 20 个 query 上反复迭代（Stage29→39 跑了至少 5 轮真实 LLM 复验）定下来的。**没有 held-out 开发集**，0.95 几乎必然是乐观偏置——这是典型的 adaptive overfitting，评审都懂这个套路。
- **单一回答模型、单一裁判供应商**。judge 和回答模型同源（qwen 系），存在自我评价偏差。
- MuSiQue utility 只有 0.40，2Wiki 是 0.95——跨数据集方差这么大，没有解释。到底哪个是真的？

### 问题 4（严重）：零外部基线

所有比较都是内部消融（自己的 Stage43 vs 44 vs 45）。**没有和任何一个已发表防御比较过**：HoG-GRAG（ACL 2026，逐跳监控+剪枝修复，和本方法相似度很高）、RAGDefender、CEG-RAG、困惑度检测、query paraphrasing，一个都没有。没有外部基线，无法回答"你的方法比现有工作好在哪里"，论文的贡献声明就立不住。特别是 HoG-GRAG——它也做 hop-wise 监控、剪枝和补充缺失证据，**界限必须在 related work 里用实验划清，而不能只靠文字**。

### 问题 5（中等）：实验世界太小、太封闭

每个 GraphRAG workspace 只有 100–120 个文档，而且基本就是 20 个 query 的 support 文档加污染版本。真实知识库是百万级文档。**在小封闭世界里**：BM25 候选恢复很容易（池子小且干净）、检索召回天然高（没有干扰文档）、攻击也更容易（上下文里就这么几篇）。两个方向的偏置都有，但都无法外推。至少需要一个"support 文档 + 大规模干扰语料"的开放设置，才知道结论还剩多少。

### 问题 6（中等）：攻击的现实性还没证明

Stage47 的自适应攻击是 post-retrieval 扰动——把检索结果拿来改，再喂给防御。**跳过了整个 GraphRAG 索引过程**：注入的桥接文档经过实体抽取、关系抽取、embedding、community detection 之后还在不在？还能不能被检索到？完全不知道。如果重建索引后攻击大面积失效，Stage47 的三个"缺口"就只是假想敌。这是当前所有自适应结论成立的前提，必须尽快验证。

### 问题 7（轻微但会被问）：效率与成本完全缺失

GraphRAG 索引本身 120 篇文档就要约 2554 秒；防御链又加了风险检测、候选恢复、扩展检索、judge 调用。每次回答的延迟、token、API 费用没有任何记录。"可部署"三个字目前是免费的。

## 三、论文里必须说清楚的内容

无论后续做什么，以下内容必须在论文中显式写明（现在散落在各阶段报告里，没有一处集中说清）：

1. **威胁模型**：攻击者能做什么（注入新文档 vs 改写现有文档）、防御者的可信根是什么（版本快照？签发来源？）、可信池从哪来。这是问题 1 的正面回答。
2. **贡献定位**：贡献到底是 (a) 一个防御方法，(b) 一套自适应攻击+评测协议，还是 (c) "恢复完整性"这个评测维度？现在三者都有，主次不清。本评审的判断：(b)+(c) 比 (a) 更独特、更站得住。
3. **指标定义**：broad/targeted ASR 的分母、utility 是否包含 partial、abstain 如何计、recovery correct/wrong/none 的判定规则。这些是评审复核数字的前提。
4. **与 HoG-GRAG 的差异**：功能对比表 + 实验对比，不能缺席。
5. **局限章节**：post-retrieval 边界、样本量、单模型、可信池假设——主动写出来，比被问出来好一百倍。

## 四、后续该做什么（按优先级）

1. **补齐攻击现实性验证**（决定课题生死，最优先）：把 Stage47 已冻结的成功攻击做成完整污染语料，重建 GraphRAG 索引，看攻击是否存活到检索和 prompt。这一步不需要改任何防御代码，产出无论正负都有价值。
2. **把可信池假设落地并做覆盖率扫描**：定义"历史快照"场景，测量池覆盖率 100%/80%/50%/0% 下 ASR 和 utility 的退化曲线。这一条曲线能同时回答评审对假设的质疑和自然桥接缺口的边界。
3. **接外部基线**：至少 HoG-GRAG（GraphRAG 专用）+ 一个通用 RAG 防御，统一输入输出做配对比较。两周复现不了官方代码就如实记录，换可复现的。
4. **扩规模、立统计**：每数据集 100+ query、干扰语料混入、阈值在独立开发集上调好再冻结、报告 bootstrap 95% CI 和 McNemar 配对检验、加第二个回答模型和不同源的 judge。
5. **形式化 recovery integrity 指标**：correct/wrong/none 三分类 + `wrongRecoveryRate` 作为主指标之一写进评测协议——这是最独特的贡献点，值得顶到前面。
6. **记录效率成本**：每配置的延迟、token、费用进主表。
7. **叙事收敛**：停止"Stage 编号堆叠"的叙述方式，把故事收束成"两难矛盾 → 检测-恢复机制 → 自适应攻防发现缺口 → 可验证证据恢复"四段论（现有材料完全够，只是讲法要换）。

## 五、最终裁决

如果以论文答辩委员会的标准现在打分：

| 维度 | 评价 |
| --- | --- |
| 工程实现与评测纪律 | 优秀 |
| 问题定义与威胁模型 | **不合格**，可信池假设未论证 |

**结论：这个课题值得继续做，但现在的形态还不能写成论文。** 它已经收集了足够多的"现象证据"，缺的是把它变成"科学证据"的三样东西：攻击端到端现实性、外部基线、统计严格性。按上面第 1–4 条推进，大约 6–8 周可以知道这篇论文是"防御方法论文"还是"攻击与评测协议论文"——两条路都是合格的硕士论文，但现在还分不清走哪条，这正是当前进度最该解决的不确定性。

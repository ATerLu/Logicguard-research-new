## 与 LogicGuard 的关系

本轮以项目 README、handoff.md 和 docs/methodology.md 所述研究范围为背景：RAG/GraphRAG 逻辑污染检测、非 oracle 可信证据恢复、多跳链完整性，以及真实索引、检索、截断提示词、回答之间的传播审计。以下是文献学习与实验建议，不表示已经实现，也不改变现有实验协议或执行资格。

**最值得补齐的三个问题。** 第一，单篇证据正常为什么仍会组合出假结论；第二，删除污染后如何找到缺失前提并确认真的足以回答；第三，怎样区分检测成功、证据改善和真实答案改善。隐私、动态入库与模型内部来源隔离作为相邻方向补充。

## 建议积累的实验问题

1. **补证收益从哪里来。** 用同一初始上下文、同一检索器、同一调用预算比较 BM25 恢复、普通查询扩展、前提驱动补证；分别看必要证据召回、属性句完整性、最终正确、拒答与费用。
2. **多源是否真的独立。** 来源 ID 不同不等于独立；将同一来源的转述归组，用 LENS/DnD 风格的联合污染检查共识和邻域防御。
3. **恢复是否制造新桥。** 对显式原文关系、实体对齐和模型推断使用不同标记；每条推断保留前提 span，禁止仅因图路径存在就升级为可信事实。
4. **指标是否藏住失败。** 并列报告固定 attempted ASR、条件 ASR、clean-correct flip、证据覆盖、非空回答正确率和 false verification rate；unknown 或工具失败不计作安全。
5. **是否能迁移。** 按来源组隔离校准、开发与测试；在不同数据集和攻击家族上检验阈值，使用配对差值及区间，保留不显著和失败结果。

这些只是学习后可讨论的设计问题，不是对冻结实验追加执行，也不意味着已取得攻击/防御效果。

## 需要特别谨慎引用的地方

- LG082 的 0.016% 修改比例只对应特定 HippoRAG2 设置，不能套到 Microsoft GraphRAG。
- LG084 的已返回攻击包 ASR 与全部尝试 E2E-Strict@5 分母不同。
- LG096 的高支持率伴随大量删声明和空回答，100 次划分也不是 100 次独立实验。
- LG102 的便宜验证器总分相近但错误放行更多；置信度路由未证明优于等预算随机路由。
- LG110 固定证据并禁用 live search，不能当作端到端语料投毒实验。
- LG112 提供经验抽取抑制，不提供差分隐私保证。
- LG118 的 85.78 是正文综合评分，不能引用为问答准确率。
- LG100、101、117 是同团队不同方法；学习时比较机制，不能当作三次独立团队验证。
- LG103 的 RAGStress 与 LG110 的 RAG-Stress 名称相似，作者、arXiv 标识和研究协议不同，已人工核对。

## 术语便签

- **充分性**：现有证据是否覆盖回答所需的全部前提；与“相关”不同。
- **血缘 / provenance**：一条证据或结论来自哪里、经哪些变换得到。
- **反事实删除**：保持其他条件不变，移除一个来源后观察答案变化；用于影响分析，不自动证明事实正确。
- **选择性回答**：允许拒答或删除不可靠声明，需同时看风险与覆盖。
- **ASR / strict-ASR / CLR / MR**：攻击成功、严格目标命中、引用洗白和特定误导率；必须随论文定义和分母引用。
- **arXiv 预印本**：公开稿件身份，不等同于独立确认的会议录用或期刊发表。

## 数量与原位置

按现有两份清单，本机收录 80 篇，对应 80 个 SHA-256 不同的 PDF。整理前以下四个目录共存了 160 份副本，同一批仓库内外文件逐个哈希相同：

| 建库时原位置（相对于当时的工作站目录） | PDF 数 |
| --- | ---: |
| `papper/` | 40 |
| `papper2/` | 40 |
| `Logicguard-research-new/papper/` | 40 |
| `Logicguard-research-new/papper2/` | 40 |

本库另外复制 80 份，约 133.35 MiB（139,825,710 字节）。未删除原副本，因此没有节省磁盘空间。

SHA-256 去重只判断文件字节是否相同，不证明所有不同文件都是不同研究工作。原始清单元数据保留作追溯；本轮各分类解读已根据本地 PDF 关键章节补充作者、版本、贡献与实验条件，并指出发现的清单差异。未逐篇联网确认正式发表，也未运行复现实验；分类是管理分类，不是发表状态认证。

## 后续如何维护

1. 另一设备同步后，先核对 SHA-256，再判断是否为同一论文的不同版本；不要直接把历史数量相加。
2. 库内 PDF 已增加分类内 `01、02…` 前缀，保留原文件名主体和全库 `LGxxx` 编号。原始四个来源目录不改；新论文使用新 LG 编号及所属分类的下一个序号，并同步索引、解读与校验清单。
3. 分类交叉的论文保留一个主分类；可补充标签，不必复制到多个主题目录。
4. 移动整个资料库时保持内部目录结构，PDF 与主要阅读链接使用相对路径。Git 归档版中指向项目代码和文档的链接已按仓库结构修正，使用这些链接需携带整个仓库；历史日志中的本机路径仅用于追溯。
5. 原始资料、研究笔记和代码分别管理，研究笔记不能作为额外论文计数。资料库不是实时同步镜像，仓库后续更新不会自动覆盖这里。
